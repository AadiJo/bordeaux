Make “fastest path” honest: minimize time only inside an allowed route corridor, under one shared physical model, and never present an invalid baseline as a faster solution.

Context

A waypoint list does not say where the robot may travel between points. An unconstrained optimizer will therefore shorten turns and cut across the field; that is mathematically correct for an incomplete problem and wrong for the driver’s intent. The allowed region must be part of the optimization problem.

The reported LeftAuto2 comparison also exposed a separate validity problem. Profiled reports 4.4845 s, while the valid fixed-path optimum is 4.520226 s. The shorter Profiled time is not a valid competing optimum: dense checks find authored angular and centripetal constraint excesses. A synthetic heading-stop interpolation bug also caused the shared post-rotation validator to disagree with the renderer.

Definition of fastest. The objective is minimum elapsed time subject to fixed waypoint order, authored stops and events, the chosen route corridor, headings/rotation policy, robot dynamics, and every path constraint. Remove the corridor and “do not cut there” has no mathematical meaning.

Recommendation

Use a two-level solver. The inner reachability pass computes the fastest valid timing for one geometry. The outer geometry pass searches Bezier variables but rejects every candidate whose centerline leaves a user-selected corridor around the authored route. Corridor distance is symmetric and segment-local, preserving route topology at self-overlaps instead of snapping to whichever branch is nearest.

LayerResponsibilityGuarantee
TimingControllable squared-speed reachability with angular, traction, drivetrain, and motor envelopesFastest timing on the sampled fixed path
GeometryBounded Bezier search evaluated by the timing solverNever leaves the selected corridor; authored path remains the fallback
ValidationIndependent dense geometry and followed-heading checksNo candidate is applicable unless it is faster and valid

Measured LeftAuto2 tradeoff

The default is deliberately tight: 0.05 m. On the reproduced path it shifts the centerline at most 0.045 m, returns 4.4526 s, and is both faster than raw Optimized and faster than the invalid Profiled number without taking the old half-meter shortcut.

Implementation steps

  1. Correct validation semantics. Keep synthetic stops as one-sided heading phase boundaries without treating them as geometric discontinuities. Protect shared/static parity with the reported mixed look-at/tangent translation-priority fixture.
  2. Constrain geometry. Sample the authored and candidate centerlines densely, compute a symmetric same-segment corridor distance, and reject candidates before the expensive timing solve when they exceed it.
  3. Make intent explicit. “Refine path” first asks for maximum centerline shift; the preview states the corridor and measured maximum shift. Apply remains explicit and undoable.
  4. Next nonlinear phase. Add modeled keep-out polygons and swept robot-footprint clearance, then replace coordinate handle search with trust-region SQP/multi-start geometry variables. The reachability solver remains the fast inner timing oracle.

Risks & mitigations

Verification

  • Exact reproduced path: shared and renderer both return valid Optimized 4.520226 s, with no fallback.
  • Default corridor result: 4.452561 s, 0.067665 s saved, maximum sampled shift 0.045261 m.
  • Differential regression covers mixed look-at/tangent translation priority and synthetic heading boundaries.
  • Geometry tests prove waypoint metadata and handle directions are preserved and maximum deviation never exceeds the selected corridor.
  • Release gates: unit suite, typecheck, renderer verification, build, Electron smoke, and packaged manifest.

Open questions

  • Keep-out authoring should be a separate field tool: polygons inflated by robot footprint, not invisible assumptions inferred from the field image.
  • A future “global” mode should expose compute budget and multi-start count; the interactive default should stay bounded and deterministic.
