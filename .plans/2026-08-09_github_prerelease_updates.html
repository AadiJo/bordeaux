Publish signed Bordeaux beta builds as GitHub prereleases and let installed macOS and Windows apps download and apply them automatically.

Context

Zw96042/bordeaux is now public, so installed apps can fetch GitHub Release assets anonymously without embedding a repository token. The existing source repository is therefore also the simplest release feed.

Recommendation

Use prereleases in Zw96042/bordeaux on an explicit beta channel. The workflow builds from an explicitly entered checked-in version, signs both platforms, and uploads matching update metadata in one final release job.

Signing is part of the update contract. macOS automatic updates require a Developer ID signature. The workflow will fail closed until the required signing secrets exist instead of publishing an update that installed Macs cannot apply.

Implementation steps

  1. Add electron-updater, configure the GitHub beta channel, check automatically only in packaged builds, and expose a manual “Check for Updates…” menu action.
  2. Add a manually dispatched prerelease workflow that validates a SemVer prerelease, builds macOS and Windows artifacts, verifies their manifests, and creates one non-draft GitHub prerelease only after every build succeeds.
  3. Require signing credentials through GitHub Actions secrets and document the exact release command and update lifecycle.
  4. Test updater state transitions with injected dependencies and run the complete package/smoke verification suite.

Risks & mitigations

RiskLikelihoodMitigation
Release feed becomes private laterlowKeep the update repository public or move both publish configuration and generated app metadata to another public feed.
Unsigned macOS update downloads but cannot installhigh without secretsRequire Developer ID signing and notarization in the prerelease workflow.
Partially published release after one platform failsmediumBuild and upload workflow artifacts first; create the GitHub prerelease in a final dependent job.
Unsaved editor work is lost during restartlowNever force installation while dirty; defer until a clean exit or explicit clean restart.

Verification

  • Six unit tests cover development/no-network behavior, automatic checks, manual status, check and download errors, download completion, downgrade prevention, and dirty-project restart protection.
  • Generated beta-mac.yml and app-update.yml point to the public repository and beta channel; package and public-manifest verification passed on a fresh macOS ZIP simulation.
  • All 186 tests, type checking, build, and the Electron smoke suite pass.
  • An independent read-only review found four release-safety blockers; all were fixed and the follow-up found no remaining blocker.

Decision

The owner made the existing repository public, selecting Zw96042/bordeaux as the beta feed. No separate binary repository or embedded GitHub credential is needed.
