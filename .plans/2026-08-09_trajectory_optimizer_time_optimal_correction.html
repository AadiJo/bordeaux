True Time-Optimal Trajectory Correction

Projectbordeaux
Versionv3
Statusdone · 2026-08-09

Make Bordeaux genuinely minimize traversal time under independently derived robot constraints, then add bounded geometry refinement as an explicit preview instead of silently moving authored paths.

Context

The current optimizedTrajectory uses each profiledSpline sample velocity as a hard ceiling and then adds motor, drivetrain, angular, and numerical margins. It therefore cannot beat Profiled. Its backward pass also stores only one controllable maximum; general affine drivetrain constraints can require a lower predecessor speed, so valid trajectories can be misclassified as infeasible.

Correctness boundary. Fixed-path timing belongs in optimizedTrajectory. Geometry movement does not: it must clone the path, solve off-thread, show the changed curve and anchored features, and require Apply or Cancel.

Recommendation

Replace the inherited Profiled envelope with explicit point and midpoint caps for authored velocity, stops, curvature, heading rate, and wheel/module kinematics. Propagate complete controllable intervals in squared speed, then greedily extract the fastest trajectory inside those intervals. Prove small instances against an independent dynamic-programming oracle and validate every accepted output densely.

After that core passes, add deterministic cubic-Bezier handle-length refinement as the first nonlinear geometry tool. Pin waypoint positions, tangent directions, headings, topology, actions, and feature identities. Include the authored path as the baseline and return unchanged rather than “unsolvable” when no material win exists.

Implementation steps

  1. Remove the Profiled sample-speed ceiling while restoring explicit stop, point, and midpoint curvature/drivetrain caps in the shared and renderer constraint adapters.
  2. Rewrite backward reachability to propagate complete squared-speed intervals. Intersect scalar motor/accel/decel limits, affine module constraints, and asymmetric angular acceleration bounds before forward extraction.
  3. Add a no-dependency exhaustive oracle for short scalar cases, the known false-infeasible regression, physical trajectory fixtures, and randomized renderer parity.
  4. Make benchmark comparisons honest: accepted Optimized output must have zero violations; Profiled time is labeled as an unsafe baseline when it fails the same dense validator.
  5. Add an off-thread Bezier handle-refinement worker with fixed evaluation ceilings, stale-result cancellation, candidate overlay, and one undoable Apply action.
  6. Run the full test/type/build/smoke/package gates, 100,000 reachability fuzz cases, optimizer corpus, and independent Codex review.

Verification

  • Known false-infeasible affine case returns the oracle-optimal profile.
  • Every curated and fuzzed accepted trajectory passes independent dense velocity, acceleration, deceleration, angular, curvature, and module/wheel validation.
  • For each valid fixed geometry, solver duration matches the short-case oracle within tolerance and is never capped by Profiled samples.
  • Geometry candidates are accepted only when valid and faster by at least max(0.020 s, 0.5%); unchanged geometry is always a safe fallback.
  • npm test, typecheck, build, smoke, shadow, benchmark, fuzz, package, and packaged-manifest checks pass.

Claim boundary

The corrected fixed-path planner may be called time-optimal only under Bordeaux’s discretized authored-path model. The first geometry tool should be called Geometry refinement, not globally optimal or Sleipnir-equivalent. A Sleipnir-comparable claim requires a later TrajoptLib oracle showing a median time gap no greater than 2%, p95 no greater than 5%, and zero safety regressions.

Outcome

The fixed-path planner now derives its own physical envelope, propagates full controllable squared-speed intervals, enforces endpoint torque falloff along every wheel module’s rolling direction, inserts exact policy boundaries, and validates on a freshly resampled curve. Heading-derivative discontinuities become explicit dynamic stops instead of optimistic finite-difference timing.

The explicit Refine path tool searches bounded Bezier handle lengths in a cancellable worker, rejects candidates with path-check errors, protects stale document/robot/planner state, and applies a winning preview as one undoable edit.

  • All 225 TypeScript tests pass, including independent oracle, endpoint module motor-envelope, resource-ceiling, dense-geometry, renderer parity, and geometry-refinement regressions.
  • The 100,000-case reachability fuzz run completed with zero unexplained failures.
  • The shadow corpus reports no both-valid slowdown: two faster, two materially equal, and five Profiled baselines invalid under the same eight-times-dense physical check.
  • Observed p95 latency is approximately 14.4 ms for common paths and 37.3 ms for the long stress path.
  • Build, Electron smoke, package creation, and packaged-manifest verification pass.
