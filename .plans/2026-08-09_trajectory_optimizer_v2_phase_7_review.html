Scope

This review covers Phase 7 code through eb4ef77e on feat/trajectory-optimizer-v2. It reviews the developer flag, renderer worker integration, aggregate storage contract, corpus command, benchmark reuse, CI/package gates, and developer documentation. No network telemetry or project-schema change is included.

Implemented behavior

  • Non-serialized opt-in: BordeauxOptimizerShadow.setEnabled(true) writes one machine-local flag. It never mutates BordeauxProject, save, autosave, Java export, or agent-session data.
  • True shadow execution: when Profiled is selected and the flag is enabled, the existing cancellable worker computes Optimized but never replaces the visible Profiled preview. An Optimized-selected project records the same aggregate as an opt-in observation.
  • Aggregate-only storage: fixed counters retain status, planner used, comparison direction, fallback/violation counts, summed/max timing, and a bounded solve-time histogram. There are no observation arrays, path IDs, names, geometry, project data, or error messages.
  • Developer report: snapshot() returns aggregates plus average timing and p50/p95 histogram upper bounds; clear() removes the report.
  • Release gate: npm run shadow:optimizer runs the production planner wrapper twice over the shared corpus, removes only nondeterministic solve duration from byte comparison, and fails on an unexpected status, accepted-output constraint violation, deterministic mismatch, or unexplained slower result.
