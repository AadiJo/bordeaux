The fixed-path optimizer now has canonical path derivatives, exact rectangular drivetrain projection, dense independent validation, adaptive refinement, and explicit safety outcomes—without introducing a generic nonlinear solver or Choreo-style latency.

Context

This is the second implementation slice of Trajectory optimizer strategy for Bordeaux. The first slice replaced heuristic velocity smoothing with a deterministic reachability core, but intentionally reported only feasible because it lacked exact drivetrain projection and dense final validation.

The goal of phases 1–4 was to make a successful result independently defensible as optimal for Bordeaux's sampled, fixed-geometry model while preserving authored geometry, stops, heading priority, translation priority, stationary actions, markers, and visible fallback behavior.

Implemented

  • Canonical path state: immutable arc length, tangent, normal, signed curvature, unwrapped heading derivatives, segment ownership, ordered waypoint mapping, and explicit stopped-phase boundaries.
  • Drivetrain-aware reachability: exact left/right wheel projection for tank and four-module projection for rectangular swerve when driveModel geometry is present. Module acceleration norms become analytic affine bounds in (s̈, ṡ²) for both backward controllability and forward extraction.
  • Dense validation: endpoint and midpoint checks independently cover boundary velocity, authored linear and angular ranges, torque-speed acceleration, deceleration, module/wheel speed, and combined drivetrain acceleration. Short ranges use interval-overlap semantics.
  • Adaptive refinement: only refinable violations increase the solve grid, with two bounded passes and a resource ceiling checked before allocation. Unresolved violations produce an explicit profiled-spline fallback rather than an unsafe optimized result.
  • Motion features: heading-priority intervals receive exact interval angular caps. Translation-priority timing is passed through the existing causal angular follower and then revalidated using final angular/module kinematics. Authored turn boundaries remain owned by the shared arrival → turn → jiggle → wait → departure postprocessor.
  • Diagnostics: successful results now expose refinement passes, validated point count, and deterministic active constraints. Nonzero translational jerk is explicitly rejected until the third-order phase exists.

Risks & mitigations

RiskLikelihoodMitigation
optimal is read as global geometric optimalitymediumThe status applies to the validated sampled fixed path. Geometry is never silently changed; optional geometry refinement remains a separate preview feature.
Missing drivetrain dimensions make module projection impossiblemediumUse exact projection only with authored wheelbase/trackwidth. Otherwise retain the aggregate robot hard-limit contract rather than inventing dimensions from bumper size.
Finite differences are noisy at stops or law boundarieslowUnwrap heading, section derivatives at stopped waypoints, use exact interval heading deltas for angular caps, and validate both sides of every moving interval.
Refinement grows unexpectedlylowRefine only localizable violations, cap at two passes, and reject the projected sample count before allocation.
