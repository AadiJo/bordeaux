Scope

This review covers the Phase 5–6 implementation through a100059d on feat/trajectory-optimizer-v2. It closes the two open items from the phases 1–4 review: a generation-aware worker boundary for the active optimized preview, and a tested numeric mirror in the canonical static renderer.

Implemented behavior

  • Immediate interaction: active-path edits always produce a synchronous profiledSpline preview first. The optimized result replaces it atomically only when its path and robot identities still match.
  • Cancellation: every request owns a generation ID and a dedicated worker. A new edit, planner change, or unmount terminates the previous worker; stale messages are ignored even if delivered afterward.
  • Visible containment: worker failures retain the immediate profiled trajectory and surface an “Optimized preview unavailable” alert rather than blanking or crashing the editor.
  • Renderer parity: trajectory-optimizer.js mirrors reachability, overlapping linear/angular ranges, drivetrain module projection, translation-priority handoff, adaptive refinement, dense validation, and diagnostics from the shared planner.
  • Planner semantics: routine and agent-candidate previews continue to honor the project’s selected planner. Project/export planner IDs and shared planner behavior are unchanged.

Performance

The shared benchmark reports optimized p95 of 0.424 ms, 1.144 ms, and 0.670 ms for the demo, curved, and range-stop fixtures. A 100,000-case reachability fuzz run completed with 0 unexplained failures. Worker startup is deliberately excluded from planner timing; the active editor continues to display the immediate profiled result during that handoff.
