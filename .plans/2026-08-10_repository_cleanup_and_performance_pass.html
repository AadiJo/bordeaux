Context

The repository already completed the highest-risk correctness and packaging remediation and, at main@ca50a45, moved the renderer from sixteen ordered globals to a Vite module build. The current baseline passes 197 tests and both existing TypeScript targets. The remaining debt is less dramatic but still broad: canonical project state carries a duplicate singular routine, the agent API still accepts a superseded goals shorthand, the renderer contains partially migrated JavaScript facades and monolithic controllers, shared and renderer path math overlap, and a stricter compiler pass exposes at least one dead parameter.

Boundary rule. Backward-compatible decoding remains only where deleting it would strand real projects or break the active MCP contract. Once decoded, project runtime state has one representation. Existing owner-created launch, marketing, prototype, and example-project edits were preserved; the example project only lost its now-redundant singular routine mirror.

Recommendation

Use a deletion-first, boundary-oriented refactor. Remove redundant runtime representations and obsolete API inputs before splitting files or inventing abstractions. Apply small performance improvements where the code currently repeats traversal, cloning, serialization, or derivation in reachable paths. Keep intentional compatibility parsers isolated and tested rather than scattering old-field checks through the application.

Implementation steps

  1. Confirm reachability. Build import/call-site inventories across TypeScript, renderer modules, Java runtime, scripts, CSS, tests, and package output. Compare findings with the existing issue board and the completed full-codebase audit.
  2. Canonicalize project state. Keep singular-routine migration in decodeProjectValue/normalizeProject, but remove the duplicate field from maintained in-memory and encoded project shapes. Update renderer state, Electron boundaries, validation, exports, fixtures, and tests together.
  3. Audit superseded agent inputs. The legacy route shorthand remains only because it is still an active registered MCP contract with callers and tests. Ordered steps remain the recommended path; removing the shorthand requires an explicit protocol-breaking version change rather than an opportunistic cleanup.
  4. Collapse local duplication. Remove dead parameters, redundant aggregate exports, repeated helpers, and unreachable CSS/assets proven unused by the current module graph. Extract shared math only where behavior is byte-for-byte or regression-tested; defer semantic consolidation that mixes preview and export post-processing.
  5. Tighten hot paths. Replace avoidable linear rescans or repeated whole-project publication where a bounded lookup, memo, or boundary projection is simpler. Record renderer bundle size and representative planner timing before and after.
  6. Verify and independently review. Run focused regressions, full npm/Java/type/build checks, Electron smoke, package validation where practical, inspect the complete diff, and have a separate Codex reviewer search for behavior loss or needless abstraction.
